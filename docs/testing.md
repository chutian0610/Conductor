# Testing & coverage

> **Source of truth:** all `*_test.go` under `server/`.
> Generated against `c2e2b7e chore(server): gofmt the codebase`.

## How to run

```bash
cd server

make test          # unit + auto-skipping live tests (~50s on macOS arm64)
make test-race     # same with -race (slow)
make test-cover    # emit coverage.out + coverage.html, print summary
make bench         # benchmarks (V1 has none yet)
```

The `Makefile` is at `server/Makefile`. `make help` lists every target
with a one-liner.

## Test layout

### Pure-Go tests (always run)

| Suite | File | What it covers |
|---|---|---|
| `TestClaude_BlocklistFiltersCustomArgs` | `claude_test.go` | `buildClaudeArgs` against `claudeBlockedArgs`, using a `/bin/sh` wrapper to capture argv. |
| `TestCodex_BlocklistFiltersCustomArgs`  | `codex_test.go`  | `buildCodexArgs` against `codexBlockedArgs`, including the resume-vs-fresh flag asymmetry. |
| `TestCodex_McpConfig_*`                | `codex_mcp_test.go` | YAML → JSON → TOML rendering round-trip for the managed-MCP flow. |
| `TestSchema_*`                         | `configschema/schema_test.go` | `Schema.Parse` / `Validate` / `ToExecOptions` plus validation error shapes. |

These never need an LLM CLI on PATH, so they run everywhere (CI, dev
laptop without Claude/Codex installed, Docker image). When the live
CLIs are missing, they are the entire test surface that runs.

### Live tests (auto-skip without the CLI)

Each suite has `TestClaude_Live_*` / `TestCodex_Live_*` tests prefixed
with `Live_`. They use:

```go
func requireClaude(t *testing.T) string {
    path, err := exec.LookPath("claude")
    if err != nil { t.Skip("claude CLI not installed; skipping live test") }
    return path
}
```

…and are skipped automatically when the binary is missing. CI runs
without Claude/Codex installed, so today it only validates argv
construction, MCP rendering, and schema validation — **the
`Execute()` lifecycle is not exercised in CI**.

> **Why no fake-binary harness yet:** the harness from the comment
> headers (`internal/agent/testhelpers_test.go`) only provides a
> logger helper and a temp-file helper. There is no fake
> `claude`/`codex` compiled at test-time. That gap is the biggest
> weakness of the V1 test surface — see "Known gaps" below and the
> follow-up note in `docs/backends/claude.md`.

## Known gaps

1. **No end-to-end subprocess coverage.** The pure-Go tests
   exercise argv, scanner, MCP, and schema in isolation. The whole
   `Backend.Execute` path (spawn → scanner → finalizer → channel
   close) has never run against a CLI in CI. Adding a
   `internal/agent/testdata/fake-claude/main.go` +
   `testdata/fake-codex/main.go` plus a `*_integration_test.go` per
   backend would lift `internal/agent` to ~95% and turn the live
   tests' assertions into permanent CI coverage. **Recommended next
   step** — see my verdict at the end of the recent session
   summary.
2. **Resume-fallback path is undertested.** `TestCodex_Live_Resume`
   happy-paths `codex exec resume` against a real Codex install, but
   the `ResumeExpected = true` fallback path (`isResumeSessionGone` →
   `shouldFallbackToFreshSession` → `resumeWithContinuityNotice`) is
   effectively uncovered. The fake-binary integration test described
   above is also the natural place to land that coverage.
3. **`providerNeedsInlineSystemPrompt` decider has no tests.** When a
   non-disk-delivery provider is added, this needs both a switch arm
   and a unit test asserting the decision.


`coverage.*`; regenerate freely.
